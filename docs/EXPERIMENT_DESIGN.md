# 实验设计与冻结协议

## 数据集

- 历史开发：`evaluation/hr_medium_dev_v2.json`，20 题 / 45 个标注证据组，保留旧 39/45→44/45 对照。
- 历史内部验证：`evaluation/hr_medium_holdout_v1.json`，12 题 / 26 组。曾发表过结果，不能叫新盲测。
- 新来源草稿：`evaluation/upgrade_dataset/candidate-v1/`，113 题、68 个文档；来源哈希、完整引文与 chunk ID 逐条校验，按政策来源簇归组。
- 新内部冻结测试：`evaluation/upgrade_dataset/internal-test-v1/dataset.json`，112 题。逐题核对问题、参考答案、限定词和引用，收紧 9 处过度扩展。U025 已在生成安全检查中见到输出，故排除。冻结 JSON 的 SHA256、语料与策略代码哈希在同目录 `freeze.json`。

新题包括事实、条件、例外、跨文档、相似政策、复合问题、地域信息不足、个人记录无答案及权限请求。它是同一公开语料上的内部测试，不是外部人工盲测。旧 holdout 转回归的记录保持原状。测试结果不用于改排序、阈值或提示词；一旦使用，应转为回归并另建测试集。

## 四方案

| 方案 | 实际执行 |
|---|---|
| B0 | 固定镜像原生选择器，关闭重排，原合并候选顺序 |
| B1 | 同版原生重排适配器，随后原生数量与 token 选择 |
| B2 | 自定义完整候选整句排序，随后相同选择器 |
| B3 | B2 加原有保守条件性子问题融合，随后相同选择器 |

**原生选择器已先重排再截断。** 必须测 B1；不可用“未开启原生重排”证明优于原生重排。历史同分数离线重放中，B1 与 B2 在 20/20 题完全同序，均为 43/45；B3 为44/45。这个等价结论是有效结果。

## 控制变量与实际执行

固定 68 文档/318 块快照、1024维 BGE-M3、固定镜像 digest、总预算40000 token、chunk_top_k20、rerank_min_score0。同题共享完整合并候选、图占用后的实际文本预算及同一供应商整句分数。B1 通过固定镜像真实原生函数执行，只有供应商打分替换为已保存的同次响应，避免重复付费。B2/B3 使用同一完整候选，不能新增金标准或候选池之外证据。

新测试在独立克隆的 9632 实验服务上获取候选；其补丁只采集、不改变原排序与选择。旧 v3 不写入。先3题验证，再扩大；复用已有尝试，不静默重试超时或失败。`scripts/run_upgrade_retrieval.py` 显式 `--execute`、数量及直接重排请求预算，保存逐题输入/响应/候选/分数/错误；mix 内部可能调用关键词模型和 Embedding，不能把上游请求次数当账单笔数。

## 指标及不可评估项

- 标注正例 Recall@5/10、MRR@10；分母是已标注正例，不冒充全量相关性真值。
- 证据组完整覆盖与整题完整率；同一块承载多个组时不是多个独立成功。
- nDCG@10 / 无关比例：存在未判相关性的返回块时记 `null`，不能把“未标注”算作无关。
- 原生选择器真实 token 数；图文本占用后的余量固定，不能把40000全算文档预算。
- 检索/重排调用耗时与离线重放耗时分别统计。离线缓存重放不可称冷服务 P50/P95。
- 输出失败题、缺失候选、B3未触发的复合题和相对退化，不能只汇报获胜子集。

## 生成、安全、性能与业务

生成评估固定提示词、模型别名与同一选择预算，记录逐项正确性、条件完整、引用支持及拒答；结构/关键词规则不能代替完整事实核验。同一问题相同上下文应复用生成，不重复付费。

真实生成安全烟测固定3个上下文，包含正常、用户注入和文档注入，最多450输出token/次、不自动重试。输出、usage及检查均保存；“无固定期限合同”触发了只匹配“永久”的评分误报，原失败保留并单列复核。

权限、越权、异常文件、重复索引、过期版本、数据库/模型失败及无证据由实际 API/SQL 或明确 mock 故障测试，说明各自运行环境。并发1/5/10/20在实际 HTTP+独立 MySQL 下运行，每档20次，模拟供应商0.1秒，仅验证业务开销与准入拒绝；不称真实模型吞吐量。

业务只进行可复现的模拟证据查找诊断。没有真实参与者，不填用户任务时间、满意度或真实企业效率提升。
